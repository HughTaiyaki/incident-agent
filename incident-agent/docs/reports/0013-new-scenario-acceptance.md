# 任务 0013 第 4 阶段：新场景验收

日期：2026-11-04。对应[任务 0013](../../tasks/0013-evidence-and-baseline.md)，规则在出题前写入[预先写定](../evaluation/0013-stage4-preregistration.md)（提交 `d0a41da`）。题目和判分都由隔离的独立会话完成，它不读 Agent 的规则和之前的报告。这是**半盲**：出题的也是同一个模型。用户随机抽检 10 份（种子 52），对判定没有异议。

## 结论

**混合流程没有通过验收，线上默认保持 `agent`。** 换成没见过的问题后，三种流程都只诊断对很少一部分。

| 条件 | 要求 | 结果 | 是否满足 |
| --- | --- | --- | --- |
| 能诊断新问题 | 8 份故障样本命中至少 2/3 | 混合 **2/8** | **否** |
| 不比其他流程差 | 不少于固定，不比动态少超过 1 份 | 固定 1、动态 1、混合 2 | 是 |
| 不乱说 | 正常样本没有误判 | 0 次 | 是 |
| | 无依据断言不超过 10% | **18/30，60%** | **否** |
| | 不可诊断样本没有编造更深原因 | 本批没有不可诊断样本；全部样本里混合组有 8 次编造 | 不适用 |
| 成本 | 平均 Token 不超过动态的 60% | 7,382 对 18,213（40.5%） | 是 |

之前三组对照里混合流程命中 14/14，这次是 2/8。**这说明泛化能力不足，但不能都算在调优头上：** 场景、判分人和冻结数据的覆盖都变了，这次分不清各自的贡献。

**这个结论只针对根因定位。** 12 次“部分对”可能已经替人找出了关键调用和错误窗口，但有些报告同时带有误导，所以不能直接相加说 23/30 有效。Agent 能不能帮人更快排查，这次没有测，要[另外测量](../../tasks/0014-assist-and-evidence.md)。18/30 是含无依据断言的报告比例，不是全部断言的 60%。

看过结果后，这 10 份样本转为开发集，不再用来验收。

## 为什么失败

这些都是这批样本暴露的问题，具体改法还没有验证。

1. **几乎不看指标。** s02 的积压和 s09 的连接池 100% 都只在指标里。固定和混合只查一个 `rpc_error_rate`，动态流程能查也没查到。这是一类盲区，和具体 bug 无关。
2. **报告围着噪声转。** s02、s08 里系统没有明显报错，混合组的报告把负载本身的 1062 和请求号复用说成主要现象，真正的积压和提前关单没有发现。三组这两份样本都是 0 次判对，我只逐条看了混合组的报告。
3. **停在症状，没判断问题在哪一侧。** 12 次部分对多数是这样：说出调用超时，没说出请求根本没到 user-service（s01）、慢在模拟器（s05）、连接池满（s09）或期限被改小（s06）。
4. **系统知识会误导。** s06 的真实期限是 8 ms，记录里调用约 8 ms 就结束，报告还是写“800 ms 期限”，这句话来自配置档。知识过期时，模型宁可信它也不看数字。
5. **没有预期行为就发现不了逻辑错误。** s08 没有任何错误记录，要知道“支付期限不该在 1 秒内到”才能发现。
6. **调用关系不是通用解药。** 混合组又出现了 3 次因果倒置，比如 s06 把取消后的数据库错误说成超时的原因，第 2 阶段的 0 次只在那批样本上成立。

**无依据断言的 60% 要这样看：** 判分人不知道系统说明的内容，把来自说明的“并发提交”“沿用已有订单”也算无依据，这类在混合组占 4 条。去掉后还有 14/30，47%，仍远高于 10%。其余是报告自己添的细节，比如“订单号不同”“重试至少三次”，有些出现在结论正确的报告里。

## 哪些是真的

- **不乱报故障。** 三组 90 次都没有把正常行为判成技术故障，2 份正常样本里混合组 6/6 判对。
- **错误信息明确时能查到。** s10、部分 s07。
- **混合流程的成本优势成立。** 平均 Token 约为动态流程的 40%，判对次数也不比它少。样本太少，不能说它更准。

## 限制

- 半盲，只换了 bug，还是同一个商城和拓扑。
- 判分人比我之前严，所以和前几轮的数字不能直接相减。
- 动态组有 12 次、混合组有 3 次查询因为冻结样本里没有对应数据而失败，线上不一定会这样，动态组受影响更多。
- 出题会话把 10 份都标为可诊断，这批没有测拒答能力。
