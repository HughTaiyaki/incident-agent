# 任务 0013 第 1 阶段：动态 Agent 和固定流程对照

日期：2026-11-03。对应[任务 0013](../../tasks/0013-evidence-and-baseline.md)，规则在运行前写入[预先写定](../evaluation/0013-preregistration.md)（提交 `18b650f`）。判分人 Claude，隐藏流程标签，但知道场景真值，所以不是盲测。用户随机抽检 10 份报告（种子 13），对判定没有异议；[定向检查](#定向检查)单独记录，不代替随机抽检。

## 结论

**按写定的规则，动态调查没有达到保留标准：** 动态 Agent 命中 22/25 份样本，固定流程 20/25，只多 2 份，没到 3 份。这不等于动态调查没有价值：两份差异都对它有利，它确实找到了固定流程遗漏的证据，只是没达到事先约定的收益门槛，而且平均 Token 约为固定流程的 2.58 倍。

**决定（用户确认）：** 固定采集作为下一阶段的候选默认，动态模式保留为对照和可选路径。“固定采集加按需补查”是第三种方案，这次没有测过：补查能否追回遗漏、触发成本多高、会不会漏触发，都没有证据，所以它只是待验证方案。

还有一处规则没反映出来：固定流程的 N1 全部算判对，但它一次也没看到 1062 错误，见[下文](#规则没有反映的地方)。

每种流程 75 次，共 150 次。接口全程健康，没有模型调用失败，没有空报告。

全部费用约 ¥1.64（含接口探测），按 Token 比例估算动态 Agent 约占 72%。

其余 23 份样本，两种流程判对的次数相同。

## 未判对的运行归类

| 类别 | 动态 Agent | 固定流程 | 场景 |
| --- | --- | --- | --- |
| 证据不足 | 6 | 6 | H2、B1：冻结样本里没有崩溃或重复扣减的直接记录 |
| 检索失败 | 1 | 6 | 固定流程的 D1、H3；动态 Agent 的 B7 |
| 解释错误 | 2 | 3 | B7 |
| 运行失败 | 0 | 0 | |
| 合计 | 9 | 15 | |

这三个类别用来定位问题，不改变上面写定的主指标。H2、B1 既算证据不足，又计入未判对，所以 39/48、33/48 是任务完成率，不是诊断准确率。下一轮提前固定[新的口径](../../tasks/0013-evidence-and-baseline.md#下一轮的评分口径)。

这说明三件事：

- **H2、B1 换哪种流程都没用：** 问题出在数据，不在查询方式。
- **B7 的主要问题是解释：** 两种流程都 0/6。关键记录大多展示过了，模型还是没说出 goods 太慢。只有 1 次把因果说反，比第四次复测少。
- **固定流程的损失集中在检索：** 这正是“证据缺口明确时再动态补查”想解决的问题，但缺口如何判断还没有设计。

## 规则没有反映的地方

**N1 的判对标准太松。** 动态 Agent 9 次都看到了 1062 错误，固定流程 0 次。固定流程的 9 次都没提到并发重复提交，其中 4 次还写了“没有记录到错误”，这个说法是错的，样本里有这条记录。结论“不是技术故障”碰巧对了，原因并不对。

如果把 N1 改成必须说出并发重复提交，差距会变成 5 份，动态调查就能保留。这是看到结果后才想到的口径，**不能据此改决定**。它说明“结果方向正确”和“解释有证据”要分开评分，不只是正常场景的标准太松。

**更大的风险是自信地漏证据：** H3 和 N1 里，模型没看到关键记录，却觉得证据够了，还写出“没有错误”。等模型自己说不确定再补查，这种情况不会触发。

## 不能外推

- **样本和提示词都调优过：** 这组对比只回答动态查询有没有增益，不代表泛化能力。
- **样本少：** 差距来自 2 份样本，换一批样本可能不同。阈值 3 是经验值，不是显著性检验。
- **重试名额没有被实测：** 这次接口健康，没有发生失败，报告调用的重试只有单元测试覆盖。
- **成本比较只在这个规模成立：** 这里只有 5 个服务，固定流程查 9 次够用。服务变多后，固定扫描的成本和遗漏都可能变化。

## 定向检查

揭开流程标签后，针对有争议的报告逐条核对冻结记录。这是有针对性地挑选，不能算随机抽检，也不是盲判。

| 场景 | 核对结果 |
| --- | --- |
| H3 | 固定流程 3 次都没看到退款记录（0/3 条），只看到付款 LATE；动态 Agent 看到了。检索失败的归类成立 |
| D1（w16） | 固定流程 3 次都没看到 `reserve outcome unknown`，但看到了 `replayed`。检索失败的归类成立 |
| N1 | 固定流程 0/9 看到 1062；其中 4 次“没有记录到错误”与样本不符 |
| B7 | 固定流程 3 次都看到了 goods 和 order 的慢 Span（各 3 条），动态 Agent 只看到 0 至 1 条。证据更全的一边也没说出 goods 太慢，主要还是解释问题 |

**“沿用了已有订单”：撤回之前的更正。** 之前我用“并发 CreateOrder 的 Span 状态都是 0”来说明这个断言有依据，理由不成立。记录支持的是：1062 错误和成功的 CreateOrder 在同一条 Trace 里，请求最后成功了。但这些 Span 上没有订单号，也没有日志写明返回了哪个订单，所以“沿用了已有订单”只是推断。

- **第四次复测：** 恢复原判，严格口径仍是 13.3%（8/60），之前写的 8.3% 作废。
- **这一轮：** 判分时我没把这类说法算进去，这次按同样口径补上 6 条（x042、x056、x060、x062、x105、x120）。这 6 条都来自动态 Agent，因为固定流程没看到 1062。这一行因此从 3/66 变成 9/66，高于固定流程的 7/66。这是揭盲后的修订，已知流程标签，判断依据是“报告写了沿用或返回已有订单”，对两边相同。

这一行不影响主指标和决策规则。
