# 任务 0013 第 1 阶段：实验预先写定

日期：2026-11-03。在运行任何对照调查之前写定并提交，看到结果后不改。范围见[任务 0013](../../tasks/0013-evidence-and-baseline.md#3-第-1-阶段建立可信对照)。

## 两种流程

两种流程用同一版本 `harness-v15`、同一模型（`deepseek-flash`，关闭思考）、同一提示词、同样的预算和校验。

| 流程 | 谁选查询 | 命令 |
| --- | --- | --- |
| 动态 Agent | 程序先扫全部服务的日志，之后由模型选 | `incident-eval investigate` |
| 固定流程 | 程序按下面的规则选，模型只写报告 | `incident-eval fixed` |

**固定流程的查询，最多 9 个：**

1. 每个服务一次 `notable` 日志查询，共 5 次，与动态 Agent 的开头相同。
2. 告警服务的 `rpc_error_rate` 指标 1 次。
3. 最多 3 条 Trace 详情。按 ERROR、WARN、其他的顺序，从 `notable` 日志里取前 3 个不同的 Trace ID。

规则由 `evaluation.FixedFlow` 实现，只读证据，不读场景信息。用模拟模型空跑过全部 25 份样本，确认查询都能在冻结数据中回放；空跑不含任何模型结论。

## 样本和运行

- **样本：** [第四次复测](../reports/0012-fixed-fault-evaluation.md#第四次复测harness-v14)的 22 份冻结样本，加由 D1 派生的 3 份 N2。每份样本每种流程 3 次，共 150 次。
- **顺序：** 分 3 轮，每轮随机打乱样本（种子 13）。每份样本的两种流程紧挨着跑，先后顺序也随机。
- **接口状态：** 每对运行前探测 5 次，成功不足 4 次就等待，最多等 8 小时。开跑后的结果全部保留，空报告算未命中，不补跑。

## 判分

- **标准：** 沿用第四次复测的判分标准和之前几轮的场景标准，N3 按用户判定（断言持续故障或未恢复才算误判）。
- **隐藏流程：** 判分表只含报告正文，用随机编号，隐藏流程、停止原因、查询和耗时。判完才揭开。
- **判分人：** Claude，非盲（知道场景真值），隐藏标签只防止偏向某一种流程。用户抽检约 10 份报告，名单在判分后按种子 13 随机抽取。

## 命中和决策规则

- **每次是否判对：** 故障和 bug 场景要主假设命中标准；正常场景（N1、N3、N4、N5）要有报告且没有误判；N2 要没有给出 DIAGNOSED。
- **每份样本是否命中：** 3 次里至少 2 次判对。
- **决策：** 动态 Agent 比固定流程多命中至少 3 份样本，才保留动态调查；否则默认用固定采集，只在证据缺口明确时启动动态补查。
- **同时报告：** 逐样本差异、Top-1、无依据断言、Token、耗时和失败分类。阈值 3 是经验值，25 份样本只够看方向。

## 失败归类

只给未判对的运行归类，按顺序取第一个符合的：

1. **运行失败：** 没有报告，或正文是模型调用失败造成的空报告。
2. **证据不足：** 冻结样本里找不到某一组关键记录。
3. **检索失败：** 某一组关键记录在样本里有，但这次运行没有展示给模型（按 `calls[].shown` 判断）。
4. **解释错误：** 每组关键记录都展示过，结论仍然不对。

**关键记录清单：** 同一组里匹配任意一条记录即可，每组都要匹配。匹配范围是记录的字段内容，按正则表达式。

| 场景 | 关键记录组 |
| --- | --- |
| D1 | `reserve outcome unknown`；`replayed` |
| D3 | `already processed` 或 `redeliver` |
| H1 | `reserve outcome unknown`；`retrying reserve` |
| H2 | `order\.recover`；进程中断的直接记录（目前没有已知匹配式，`panic` 或 `crash` 或 `signal`） |
| H3 | `arrived after the order started closing` |
| H4 | `already processed` |
| C2 | `reserve outcome unknown`；`replayed` |
| B1 | 重复扣减的直接记录（`deducted twice` 或 `double`） |
| B3 | `Unknown column` 或 `1054` |
| B6 | `GetConsignee` |
| B7 | `context deadline exceeded`；goods-service 的 ReserveInventory Span（耗时超过 800,000 微秒） |
| B8 | `stale snapshot` |
| N1 | `1062` |
| N3 | `context deadline exceeded` |
| N4 | `ALREADY_RELEASED` |
| N5、N2 | 无 |

场景编号和注入内容见[结果报告](../reports/0012-fixed-fault-evaluation.md)。这份清单由 Claude 根据之前几轮的样本写成，看过这些样本，不是盲写。

## 限制

- 提示词针对这些场景调过，而两种流程都用它。这组对比回答的是动态查询有没有增益，不代表泛化能力。
- 这些样本是开发集，B7、N3 也已被分析过。
- 报告阶段最多展示 24 条记录，两种流程都受这个限制。
