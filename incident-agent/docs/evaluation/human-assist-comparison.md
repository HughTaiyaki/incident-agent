# 人工辅助排障对照

日期：2026-11-04。对应[任务 0014](../../tasks/0014-assist-and-evidence.md)，补上[评测方案](plan.md)第 8 节一直没有做的业务效率对照。用户决定先由本人单独试。开始前写定并提交。

## 要回答的问题

人拿到 Agent 的报告后，能不能更快、更有依据地继续排查？根因命中率继续记录，但不决定这个问题。

## 怎么比

| 组 | 工具 |
| --- | --- |
| 对照 | Jaeger、Loki、Prometheus |
| 实验 | 同样的工具，加 Agent 报告（混合流程） |

- **场景：** 新开的隔离会话出 6 个没见过的场景，和之前所有场景不同。真值由它保管，编号打乱。
- **参与者：** 用户本人，1 人。**结果只算观察，不算比较。** 参与者了解这个商城和之前的 bug，比普通值班人员有优势。
- **避免记住答案：** 每道题只做一次。3 题只用工具，3 题加 Agent 报告，由隔离会话随机分配，交替出现。先做的题可能让后面的题更快，这点无法完全避免。
- **环境：** 只读，遥测窗口和采样一致。不看商城源码。每题上限 20 分钟，到时记录当时的结论。
- **工具：** Jaeger 界面、Prometheus 界面，日志用 `incident-query`，这些是现有的遥测入口。
- **报告：** 混合流程跑一次，提前生成。不看没有分配到的报告。

## 记录什么

| 关注点 | 怎么衡量 |
| --- | --- |
| 是否节省时间 | 从开始到确认关键线索、确定有效下一步的时间，包括阅读、等待和核查报告的时间 |
| 是否减少重复工作 | 查询次数、跨工具切换次数、手工关联的步骤 |
| 是否造成误导 | 是否因报告去了错误组件、相信了不存在的事实，纠正花了多久 |
| 是否保留诊断质量 | 最终结论和下一步检查是否有依据；根因是否命中 |

隔离会话在采样前按场景写好“关键线索”和“有效下一步”的定义。全部做完后由它判定，判定时看不到这道题有没有用 Agent。

## 判定标准（待确认）

加 Agent 的 3 题全部满足才算“观察到帮助”，否则如实记录：

1. 到达关键线索的中位时间比只用工具的 3 题更短。样本太少，只看方向，同时报告逐题差异。
2. 没有一道题因为报告走错方向后没能纠正。
3. 有效下一步的判定不比只用工具的题差。

单人结果不用来决定线上默认，也不外推。

## 不能得出的结论

人数和场景都很少，只能说明方向，不能外推到生产，也不能换算成节省的人力成本。
