# 任务 0013 第 3 阶段：实验预先写定

日期：2026-11-03。在运行对照前写定并提交，看到结果后不改。范围见[任务 0013](../../tasks/0013-evidence-and-baseline.md#4-后续阶段)。

## 设计前查到的原因

先查了固定流程为什么漏证据，因为这决定了怎么补：

| 场景 | 关键记录 | 原因 |
| --- | --- | --- |
| H3、D1 的 1 份样本 | 一条 WARN 日志 | **查到了，但没放进报告输入。** 报告最多展示 24 条记录，各查询轮流取，一条 Trace 就有几十个 Span |
| N1 | Trace 里的 1062 错误 Span | **没查到。** 日志里没有警告，固定流程只按日志选 Trace |

所以混合流程不只是多查，也要改报告输入的选择。

## 三组

三组都用 `harness-v15`、同一模型（`deepseek-flash`，关闭思考）、相同预算，都带[调用关系](../reports/0013-call-relations-comparison.md)。

| 组 | 命令 | 查询 | 报告输入 |
| --- | --- | --- | --- |
| 固定 | `fixed -relations` | 5 次日志、1 次指标、最多 3 条 Trace | 现有选择规则 |
| 动态 | `investigate -relations` | 5 次日志后由模型选 | 现有选择规则 |
| 混合 | `hybrid -relations` | 5 次日志、1 次指标、1 次 Trace 搜索，剩下的步数按缺口补查 | 先放不同种类的警告和错误，并加 `coverage` |

**混合流程的缺口规则，由程序检查，按顺序：**

| 缺口 | 动作 | 记录代码 |
| --- | --- | --- |
| `notable` 日志被截断（每次运行最多补一次） | 查 ERROR 日志 | `TRUNCATED_LOGS` |
| 有警告或错误日志，它的 Trace 还没打开 | 打开这条 Trace | `SEVERE_LOG_TRACE` |
| 搜索结果里有失败 Span 的 Trace 还没打开 | 打开这条 Trace | `ERROR_TRACE` |
| 有带 `attempt` 字段的重试日志，Trace 还没打开 | 打开这条 Trace | `RETRY_TRACE` |
| 没有缺口 | 打开任意未打开的 Trace | `DEFAULT_TRACE` |

**`coverage` 报告的内容：** 失败的查询数、被截断的查询数、未打开的失败 Trace 数、没展示的警告种类数、缺一侧记录的调用数。说明文字要求：数字大于 0 时，不能写没有错误或全部成功，要说查了什么、其余没查。

**没有实现的缺口：** 任务表里“有消息发送但消费结果未知”这一条没有实现。现有遥测里没有不依赖具体系统的字段能配对发送和消费，强行写就会变成针对商城的规则。

报告选择和 `coverage` 只对混合组开启，线上流程不变。

## 样本和运行

- **第 1 阶段的 25 份样本。** 这些样本的缺口规则正是根据它们设计的，所以追回遗漏不能说明泛化能力。
- **3 份“证据不完整”样本，**用来测“自信但证据不完整”：w12（H3）去掉日志，w09（N1）去掉 Trace，w21（B7）去掉 Trace。
- **次数：** 每份样本每组 3 次，共 252 次。分 3 轮，每轮随机打乱（种子 39），同一份样本的三组紧挨着跑，先后随机。
- **接口状态：** 每组运行前探测 5 次，成功不足 4 次就等待，最多 8 小时。开跑后的结果全部保留，不补跑。
- **余额：** 估计约 ¥2.6，低于 ¥0.8 就停。如果中途停止，只比较三组都跑完的轮次。

## 判分

沿用[第 2 阶段的判分](0013-stage2-preregistration.md#判分)，隐藏分组标签，用户抽检 10 份（种子 39）。混合组的报告可能提到 `coverage`，所以隐藏不完全。

另外记录：

- **N1 的解释：** 是否说出并发重复提交，并引用了 1062 记录。
- **不实的“没有错误”：** 报告写没有错误或全部成功，而样本里有相反的记录。
- **证据不完整样本：** 是否在证据缺失时断言没有问题，或说出没有记录支持的原因。
- **触发情况：** 每种缺口的触发率、追回的遗漏（H3、D1 的 w16、N1 的 1062）、未触发的遗漏、实际 Token。

## 决策规则

全部满足，混合流程才成为第 4 阶段的候选默认。否则固定流程仍是候选默认。动态流程无论如何都保留作对照。

1. **追回遗漏：** 可诊断样本（14 份）的命中数，混合比固定至少多 1 份，且不比动态少超过 1 份。
2. **减少不实断言：** 混合组不实的“没有错误”次数严格少于固定组。
3. **没有退步：** N2 给出 DIAGNOSED 仍是 0，正常样本没有误判，因果倒置和无依据因果断言不多于固定组。
4. **成本可接受：** 混合组的平均 Token 不超过动态组的 60%。

阈值是经验值，不是显著性检验。

## 限制

- 规则是看了 H3、D1、N1 之后设计的，虽然不提任何服务和场景，但这些样本已不干净。泛化能力要到第 4 阶段用新场景验收。
- 混合流程的步数和其他两组相同，补查会占用打开 Trace 的名额。
- 缺口规则只能发现证据里看得出的遗漏，看不出来的仍然会漏。
