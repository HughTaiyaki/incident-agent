# 任务 0013 第 4 阶段：实验预先写定

日期：2026-11-04。在出题和采样之前写定并提交，看到结果后不改。范围见[任务 0013](../../tasks/0013-evidence-and-baseline.md#4-后续阶段)。

## 要回答的问题

混合流程在没见过的场景上还行不行，能不能考虑作为线上默认。

## 出题和判分

- **出题人：** 用户决定由隔离的独立会话出题。它不共享这边的上下文，不读 Agent 的规则代码和之前的评测报告。这是**半盲**：出题的也是同一个模型，思路可能相近，结论要标明，不能当作最终验收。
- **隔离方式：** 真值放在 `data/eval/truth-stage4/`，判分前这边不读。出题会话只告诉这边样本编号，不说明场景内容。
- **场景：** 8 至 10 份新样本，和已用过的场景不同。至少 5 份可诊断的故障，故障位置和类型要分散；至少 2 份正常行为；可以有证据不足的场景。在任何调查运行前，出题会话写好判分标准，并只看冻结遥测确认每份样本是否可诊断。
- **判分人：** 出题会话，隐藏流程标签。用户抽检 10 份，按种子 52 随机抽取。

## 三组

三组都用这个提交的代码，`harness-v15`、`deepseek-flash`（关闭思考）、`goframeshop` 配置档，都带调用关系，预算相同：固定 `fixed`、动态 `investigate`、混合 `hybrid`。跑完之前不改代码和提示词。

每份样本每组 3 次，分 3 轮，每轮随机打乱（种子 52），同一份样本的三组紧挨着跑，先后随机。接口探测和不补跑的规则沿用第 3 阶段。

## 分开统计

- **可诊断样本：** 3 次至少 2 次判对算命中。
- **不可诊断样本：** 是否如实说明观察到的现象，是否编造更深的原因。
- **正常样本：** 是否误判，解释是否有证据。
- **结论方向和解释证据分开：** 结论对但没有证据，不算解释正确。
- **无依据断言：** 因果倒置、无依据的因果或数字、错误的事实，分母是全部主假设。
- **未判对的运行归类：** 运行失败、证据不足、检索失败、解释错误，依据出题会话写好的关键记录清单。
- **触发情况和成本：** 各缺口规则的触发率、Token、耗时。

## 决策规则

全部满足，才提议把混合流程作为线上默认，是否切换由用户决定：

1. **能诊断新问题：** 混合组命中至少 2/3 的可诊断样本。
2. **不比其他流程差：** 混合组命中数不少于固定组，且不比动态组少超过 1 份。
3. **不乱说：** 正常样本没有误判，不可诊断样本没有编造更深的原因，无依据断言不超过全部主假设的 10%。
4. **成本可接受：** 混合组平均 Token 不超过动态组的 60%。

否则线上默认保持 `agent`，分析失败原因。**无论结果如何，都不针对这批样本修改后再用它们验收**，看过结果后它们转为开发集。

阈值是经验值，样本数只够看方向。

## 限制

- 半盲，而且只在同一个商城上换了 bug，没有验证不同的系统。
- 每份样本的 3 次重复不是独立场景。
