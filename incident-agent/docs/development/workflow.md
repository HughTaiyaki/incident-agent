# 工作流程与文档维护

更新：2026-11-01。适用于仓库开发、文档修改和验收交接。固定边界见 [AGENTS.md](../../AGENTS.md)，内容入口见[索引](../index.md)，按需阅读路径见[阅读指南](../reading-guide.md)。

## 1. 按复杂度工作

| 情况 | 执行方式 | 必要验证 |
| --- | --- | --- |
| 解释、查询、文档、配置、格式化、单文件小改动、明确低风险修复 | 直接完成；不默认写计划、创建设计文档或工作树；不使用 subagent，除非用户明确要求 | 检查受影响事实/行为；不强制完整 TDD |
| 普通功能、范围明确的 Bug | 按需系统排查，明确切片，优先补回归测试；不删除已有实现重走严格 TDD | 受影响测试和必要集成验证 |
| 跨模块新功能、架构调整、大型重构、明显需求歧义、复杂未知根因、高回归风险或预计超过 30 分钟 | 按需完成设计、实施和验证流程；关键歧义先澄清 | 覆盖关键边界和失败路径，记录验收证据 |

用户要求“直接做”或“轻量模式”时使用简单流程；明确要求完整流程或严格 TDD 时遵循其要求。并行代理不是默认步骤，只有符合用户授权及当前工具规则、任务可安全拆分且有明显收益时才考虑。

修改前说明范围和验证方式；按已授权目标持续完成。文档任务只维护文档，不因为存在当前开发任务就自动开始功能实现。Go 编码、审阅、调试或配置时先加载可用的 `golang-how-to` 技能，再按其路由加载必要技能。

## 2. 验证入口与选择

命令在 `incident-agent/` 运行，以 [Makefile](../../Makefile) 和 [go.mod](../../go.mod) 为准。当前最低 Go 版本为 1.26.10；不从上游商城复制版本约束。

| 改动/目的 | 当前入口 | 注意事项 |
| --- | --- | --- |
| 仅 Markdown | 本地链接/锚点、围栏、事实状态、入口一致性检查 | 不要求运行业务测试，不把文档检查写成功能验收 |
| 构建、运行现有骨架 | `make build`、`make run` | API 配置与健康检查限制见 README |
| Go 格式与静态检查 | `make fmt`、`make vet` | fmt 会改写文件，完成后检查差异 |
| 行为回归 | 受影响包测试、`make test` | 测试覆盖可观察行为；不削弱断言通过测试 |
| 并发、取消、共享状态 | `make test-race` | 按改动风险执行，不能用无竞态报告代替协议验证 |
| Lint / 完整本地检查 | `make lint`、`make verify` | 固定版本工具由 Makefile 调用；verify 包含 fmt、vet、race 和 lint |
| 发布工程验收 | `make release-check` | 格式只检查不修正；含 Redis 恢复与漏洞门槛，详见[发布检查](release-checks.md) |
| 后端接入或真实诊断 | 当前任务规定的实际请求、脱敏响应、人工证据报告 | 显式记录环境和依赖；尚无 eval-offline、eval-online、demo target |
| 模型 HTTP 与预算 | `go test ./internal/app/investigation ./internal/adapter/outbound/modelhttp ./cmd/incident-model` | 默认只运行本地模拟服务；真实供应商需显式配置并单独记录 |
| 离线调查与 Report Guard | `go test ./internal/app/investigation ./internal/adapter/outbound/scripted ./cmd/incident-investigate` | 不联网；样本运行与限制见[离线指南](offline-investigation.md) |
| Redis 协议/Worker 恢复 | `make test-redis` | 自行启动独立 Unix socket Redis；需要 redis-server/redis-cli，不连接商城缓存；包含真实进程退出及租约等待 |
| 三源在线契约 | `make test-integration` | 显式指定 INCIDENT_INTEGRATION_QUERIES；环境/数据缺失时失败，详见[使用指南](../integration/query-adapters.md) |

检查通过后不无故反复扩大测试范围。检查未执行、依赖缺失或失败时如实记录；Fake Provider 测试不能代表真实模型准确率，源码存在不能代表在线验收通过。

## 3. 每类内容只维护一处

| 内容 | 维护位置 | 其他文件如何引用 |
| --- | --- | --- |
| 每次工作都需遵循的边界 | [AGENTS.md](../../AGENTS.md) | 工作区入口只指向项目规则 |
| 当前可用能力、运行命令 | [README](../../README.md) | 设计文档引用当前状态，不另写完成清单 |
| 整体范围、架构图、选型理由 | [03 主设计](../../03-日志诊断Agent详细设计.md) | overview 和索引负责导航 |
| 上游版本、源码事实、接入缺口 | [代码基线](../integration/goframeshop-baseline.md) | 引用固定 SHA；不把记录核对日期当本次实测日期 |
| 字段语义、查询与来源质量 | [遥测契约](../telemetry/data-contract.md) | 任务和执行协议引用对应章节 |
| 状态、接口、预算、证据、恢复、工作台协议 | [调查设计](../architecture/investigation-design.md) | 默认值在此维护；主设计摘要若涉及相同数值同步更新 |
| 样本、真值、分母、判分与发布门槛 | [评测方案](../evaluation/plan.md) | 任务只列当前切片的验收项 |
| 当前实施范围、验收与交接 | 当前 `tasks/` 文档 | README、AGENTS、索引均指向有效任务 |
| 目标简历表述与证据门槛 | `04-IncidentLens简历目标稿.md`（本地文件，不入库） | 未实现/未实测不改为完成经历 |
| 阅读层级、触发条件、停止规则 | [阅读指南](../reading-guide.md) | 新文档按任务挂入导航，不设全量必读 |

新增专题只有在出现独立、可按需读取的契约时才拆分；每份专题开头写适用范围、状态与权威来源。优先补链接，避免新增一份内容相同的完整设计或另建 agent.md 规则副本。

## 4. 变更时同步什么

| 变更 | 必须核对的关联内容 |
| --- | --- |
| 上游 SHA/后端版本升级 | 按基线 §5 核对源码 → 更新遥测映射 → 复核/版本化 Fixture 与评测 → 更新受影响任务、README 和主设计中的基线摘要 |
| 工具、schema、预算或状态协议变化 | 更新调查协议 → 同步涉及的遥测和评测契约 → 更新当前任务；数值变化检查主设计摘要 |
| 字段语义、查询模板或聚合口径变化 | 更新遥测契约 → 复核调查工具、脱敏/回放样本和判分依据；不静默改旧真值 |
| 实现能力或命令新增 | 核对代码、依赖、退出码和验收结果 → 更新 README、任务状态；确实影响固定约束时再更新 AGENTS |
| 当前任务切换 | 旧任务记录完成证据/遗留项 → 新任务明确范围与验收 → 同步 AGENTS、README、索引及其他指向“当前任务”的链接 |
| 文档新增、拆分、改名或章节调整 | 更新索引、阅读指南和所有入链/章节号；历史入口保留替代说明 |
| 整体方向改变 | 同步主设计和专题；需要保留取舍时写 ADR，旧 ADR/任务标替代关系 |

重要文档和接口决定写入 [changelog](../changelog.md)，列出改动、依据、实际验证和未执行项。维护已有规则时优先更新原文，避免在末尾叠加冲突的补充条款。

## 5. 完成与交接

- 确认链接目标、章节引用和代码围栏有效；目标命令确实存在，默认值与所属专题一致。
- 保留上游 SHA、本仓库版本；工作区尚未提交时注明这一事实，不伪造提交号。评测另保留模型/策略/样本版本、实验条件与分子分母。
- 区分源码核对、上游记录、本地实测、目标设计；文档整理不会使任务验收框自动完成。
- 总结改了什么、为什么、实际验证结果及剩余缺口；未运行商城、模型或业务测试时明确说明。
- 废弃文档只用于历史追溯，保留替代链接，不恢复为当前实施入口。
