## 范围和取舍

当前单 Worker 顺序执行、Redis 租约与 checkpoint 足够支持这一规模，暂不引入消息队列。只有明确出现任务分发吞吐、多个消费系统或投递管理需求，再以测量结果评估；即便引入队列，预算、checkpoint、幂等和 fencing 仍保留。

不把真实供应商、支付/退款或故障注入权限混入工程测试。P2 先在本地模拟服务验证，再使用操作员明确提供的模型配置做受控调用；P5 若需要修改/操作商城，先提交具体范围供审查。

## 发布判定

P0 通过只表示工程检查和已知漏洞门槛通过，不意味着模型诊断准确或服务可以公开部署。对外部署至少需要对应环境的 P1–P4 门槛；诊断效果声明还需要 P5。已知风险、未运行检查、外部环境依赖都必须保留在发布记录中。
