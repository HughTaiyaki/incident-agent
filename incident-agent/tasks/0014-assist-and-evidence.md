# 任务 0014：先帮人排查，再提高定位能力

日期：2026-11-04。状态：**工程部分已完成，人工辅助对照等确认。** 接续[任务 0013](0013-evidence-and-baseline.md)和[新场景验收](../docs/reports/0013-new-scenario-acceptance.md)。

## 目标

下一阶段要证明的是：**即使根因未定，人拿到这份报告后，能更快、更有依据地继续排查。** 根因命中率继续记录，但不单独决定项目是否有用。

新场景验收里混合组有 11 次判对、12 次部分对，但 18/30 份报告含无依据断言。“不知道连接池为什么满”可以接受，把它说成连接泄漏就可能让人走错方向，所以压低误导排在提高命中率前面。

## 已实现的内容（`harness-v16`）

**报告适合人接着查：** 报告增加 `narrowed_to`（证据把范围缩小到哪里、哪些解释还成立）。每条 `next_actions` 要写清检查什么、能区分哪些解释。没观察到的就写没观察到：缺服务端 Span 不等于请求没有到达，采样、截断和导出失败都可能造成缺失。

**有界指标覆盖：** 混合流程在原有的 16 次后端请求预算内，增加延迟、积压和积压年龄，以及失败调用指向的服务的连接使用和等待。查询名额分配是 5 次日志、1 次 Trace 搜索、4 个指标、最多 1 次补查日志、3 条 Trace、2 个连接指标。报告输入新增 `metrics`，分开“查到的数字”“没有数据”“没有查”，并标出只增不减的序列。程序选查询不花模型调用，所以这个流程的决策步数上限放宽到 20，模型调用上限不变。

**知识与观测冲突：** 系统说明改写，区分错误码含义、业务约定和文档预期（配置档 `goframeshop-2f25dc5-v2`）。配置档新增 `expectations`，写明来源。调用超时明显偏离文档期限时，调用关系标 `deadline_conflict`，并给出两个数字。期望的报告是这样的：

> 配置说明记载预期调用期限为 800 ms，本次记录显示约 8 ms 即超时，两者不一致。需要核对运行时配置及上游传入的剩余期限，目前不能确认具体原因。

这里只覆盖调用期限，**还不能表达“本次生效配置”**，遥测里没有这项数据。提前关单这类业务预期也还没有做。

**报告事实约束：** 程序校验事实和主假设里的时长、百分比是否有记录对应；证据有明显缺口时不能断言没有错误；一条日志和 Span 都没有时不能下结论。不通过就退回修改，修不好的那一条会被删掉。因果是否成立仍要人工判断，校验器解决不了全部幻觉。

## 回归结果（旧样本，不是成绩）

38 份看过的样本（第四次复测 22 份、N2 3 份、证据不完整 3 份、新场景验收 10 份）用混合流程各跑 1 次。这一轮只查工程问题，没有判分，不能和之前的成绩比较。

回归抓到两个问题，已修：

| 问题 | 表现 | 修复 |
| --- | --- | --- |
| 模型照抄主假设的结构，把 `narrowed_to` 包了一层 `claim` | 38 次全部被退回，平均 Token 涨到 23,554 | 提示词写明结构，并去掉这层包装，内容照常校验 |
| 数字校验没算上指标和调用关系里的数 | 第二轮有 23 次退回，平均 Token 13,578 | 把两者算进去 |
| 指标变多后，只有指标的 N2 有 1 次给出 DIAGNOSED | 第 1 阶段起一直是 0 | 没有日志和 Span 时不能下结论 |

修复后：38 次全有 `narrowed_to`，平均 Token 8,883（上一版约 6,900），N2 3 次都是 INCONCLUSIVE。退回 6 次（“没有错误”3 次、引用 3 次），另有 2 次格式错误，2 次用完修改机会。数字校验这轮 0 次退回，所以它现在只能挡住明显不符的数字，没有证据说明它减少了多少误导。
