# 任务 0009：在线持久调查与供应商联调

日期：2026-11-01。状态：**工程切片与本机真实后端运行已完成；真实供应商联调待操作员提供配置。** 依赖[0008 容量与终态](0008-capacity-and-results.md)，对应[路线 P2](../docs/development/production-roadmap.md)。

## 目标与范围

- 为 incident-worker 增加在线只读遥测查询，复用现有 Adapter、范围校验和持久预算；Fixture 模式保留。
- 每次真实后端请求（含重试）先持久扣费；模型或查询中断后按现有恢复窗口继续，不重发 UNKNOWN 操作。
- 先在本地模拟服务验证失败路径，再由操作员提供模型配置做受控调用。
- 留存脱敏证据和真实兼容性结果，与工程测试分开记录。

不包含 HTTP 入口、部署或商城改动；固定故障集验收属于 P5。

## 实施决定

- enqueue/work 必须在 `-fixture` 和 `-live` 中选一个；三个后端地址显式配置，没有默认值。后端地址的 hash 冻结进 Job，配置变化时恢复会停止。
- 单次模型或查询超时记为调用失败并继续，不再让 Worker 退出；只有 Worker 上下文结束才把工作留给恢复。
- 查询结果不得占用后续模型决策和失败记录所需的存储额度，超出的结果记为 `RESULT_TOO_LARGE`，不保存记录。
- 发往模型的记录把业务 ID 换成按 Run 加盐的假名；Trace/Span ID 保留，因为模型要用它继续查询。Redis 中的冻结证据保留真实值，新增 export 模式输出匿名 Bundle 用于留存。
- Harness 生成的失败结果来源标为 `harness`，不再标为 `fixture`。
