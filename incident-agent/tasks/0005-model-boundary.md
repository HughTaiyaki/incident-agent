# 任务 0005：有界上下文、模型预算与 HTTP Provider

状态：**本切片完成（2026-10-31）；真实供应商与生产部署未验收。**目标是让现有调查内核能够通过显式配置调用真实模型，同时具备输入约束、预算、失败收尾和可核查调用记录；不宣称整个系统已生产就绪。

## 实施顺序与验收

- [x] 构建确定性有界上下文，保留范围、最近来源质量、引用与省略标记；不传整包日志/查询正文。
- [x] 每 Run 总额度 24,000，调查保留 3,000 报告额度，单次输出最多 1,500；发出前扣预算，usage 缺失或失败保守消耗，超出预留停止后续调用。
- [x] Provider 采用显式配置的 Chat Completions JSON 协议；HTTPS（本机回环可 HTTP）、固定地址、无代理/重定向（只对 429、503 有界重发，见 Provider 指南）、有界响应与 context 超时；密钥不进入产物和错误正文。
- [x] 独立 incident-model CLI 使用冻结 Fixture 调查，保留既有完全离线命令；模型模式显式联网，不启动商城。
- [x] Run 保存调用配置、上下文摘要、预算与 usage 状态；非法模型决策仍受现有 Guard 约束。
- [x] 本地 HTTP 模拟服务测试正常循环、拒绝/超时/截断/缺失 usage/超额/越界和报告预留；verify/build/依赖与文档检查通过。

## 实现边界与生产门槛

采用保守 UTF-8 字节估算和固定消息开销，标为 estimated，不能保证供应商账单硬上限。ContextWindow 由部署者按实际模型配置；不预设型号或价格。未配置 Provider 时不访问外部模型，不读取或输出既有密钥。

目前仅单进程单 Run：调用审计未持久化到 Redis，中断后的未知计费不支持恢复执行。真实供应商兼容性、固定版本故障集效果、身份认证、网络隔离、持久调度与恢复仍需后续验收；商城改动须先提醒用户审查。
